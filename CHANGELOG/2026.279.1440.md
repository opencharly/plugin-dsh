# 2026.279.1440 — fix(dsh): assert the /api/* surface in the web probe + retire the single-layer auth claim

## Summary

The shared `dshWebTokenProbe` fragment (`candy/plugin-dsh/webprobe.go`) — used by
BOTH the `dsh: web-running` verb and `charly dsh status` — authenticated with the
launch token and then `curl`'d the root `GET /?token=…` **only**. `dsh web`
authenticates at **two** layers:

1. the per-process **launch token** (root `GET /` → 303 + cookie; tokenless → 401), and
2. the **Host/Origin browser-trust fence** (`dsh-client-connection`'s
   `api-request-trust`) — every `/api/*` call passes it **before** authentication; a
   non-loopback / forged `Host` returns **403**.

A `GET /`-only probe cannot see the fence, and the `dsh-cli` skill repeated the
now-known-false single-layer claim ("dsh-web-app >= 0.1.5-rc.x authenticates every
request").

This change:

- **`webprobe.go`** — after the token exchange, make one `/api/*` call with the
  cookie. The exchange failure **propagates** (so layer 1 is still asserted exactly as
  before), and the `/api/*` call rejects **403** (the fence), **000** (no response)
  and **5xx**. Document both layers and the `--trusted-host` **host-side** requirement —
  which this in-box probe (always dialing `127.0.0.1`) cannot itself observe, stated so
  nobody reads more into a green run than it earns.
- **`webprobe_test.go`** — lock in the propagation and the 403/000/5xx rejections.
- **`charly.yml`** (`dsh-cli` skill + the candy-entity wording) — retire the false claim.

Closes #11.

### Addressing the round-1 BLOCK

**#1 (R4a/R10 regression).** Appending the `/api/*` call made the fragment's exit
status the final `if`, silently discarding a failed token exchange: a bad/expired
token gave `C=401`, the `if` was false, and the probe exited **0** while layer 1 was
broken. The exchange now propagates via `|| { echo …; rm -f "$J"; exit 1; }` on the
cleanup path. **#2 (overclaim).** `if [ "$C" = "403" ]` failed only on exactly 403, so
`000`/`401`/`404`/`5xx`/`3xx` all exited 0 while the prose claimed the API "actually
answers". The assertion is now a `case` rejecting 403/000/5xx, and the prose at every
site says precisely that. **#3 (sweep accuracy).** The false single-layer claim lived
in the `dsh-cli` skill, **not** the candy entity — the candy entity described the UI
as "token-authenticated" (accurate). Its wording is still tightened to match the
probe; the body no longer overstates which site carried the claim.
